# Decision record

| ID | Decision | Rationale |
|---|---|---|
| D-001 | Name the project **RetreatBench** | Precise, memorable, and aligned with goal-retreat behavior; avoids collision with existing “AvoidBench” projects |
| D-002 | Treat the benchmark as a behavioral overlay | Preserve existing task difficulty, ecological validity, and original verifiers |
| D-003 | Run complete pinned upstream revisions | Avoid scope reduction; subsets are engineering fixtures only |
| D-004 | Keep capability and behavior scores separate | Prevent arbitrary weighting and preserve mechanism interpretability |
| D-005 | Define the technical construct as Recoverable Goal Retreat | Convert the narrative “avoidant personality” into a falsifiable event definition |
| D-006 | Use same-state continuation as the primary causal validation | Distinguish capability failure from recoverable retreat |
| D-007 | Require same agent/model, native resume, exact state, and residual budget for Evidence A | Establish the strongest self-recoverability evidence |
| D-008 | Let candidate detectors nominate rather than decide | Avoid language-style judgments becoming causal labels |
| D-009 | Preserve native Harbor task digests | Maintain upstream comparability and reduce adapter drift |
| D-010 | Publish no single capability–avoidance composite score | Avoid hiding qualitatively different failure mechanisms |
| D-011 | Use “personality” only after stability analysis | Prevent overgeneralization from isolated trajectories |
| D-012 | License framework code under Apache-2.0 while preserving upstream licenses | Enable research use without mislicensing third-party assets |
